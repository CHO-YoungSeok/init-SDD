## Context

이 저장소는 실행 코드가 없는 지시문 저장소다. 만드는 것은 **문서 한 개**
(`.claude/skills/init-sdd/SKILL.md`)이고, 그 문서가 곧 실행 절차다. 왜 필요한지는
`proposal.md`의 `## Why`를, 사용자가 정한 것은 `decision.md`를, 요구사항은
`specs/distribution/init-sdd-skill/spec.md`를 봐라. 여기서는 **어떻게**만 다룬다.

지금 상태에서 설계를 붙잡는 사실 네 가지:

1. `install.sh:73-78`이 에이전트와 스킬 2개, `settings.json`을 대상 프로젝트로 **복사**한다.
   복사된 파일은 공유 저장소에 커밋될 수 있는 자리에 놓인다.
2. `install.sh:84-93`이 `CLAUDE.md` 조각을 이 저장소 `CLAUDE.md`의 마커 구획에서 뽑는다.
   조각 원본이 저장소 전체에 **한 벌**인 것은 메인 spec
   `distribution/sdd-install-script`의 요구사항이다. 새 스킬도 같은 원본을 써야 한다.
3. `.claude/` 안에는 소유자가 다르다. 개인 것(에이전트, `orchestra`,
   `agent-model-tier`, `settings.json`)과 openspec CLI가 대상 프로젝트에 직접 까는 것
   (`openspec-*` 6개, `commands/opsx/`)이 한 디렉터리에 섞여 있다.
4. 이 저장소는 곧 다른 경로로 옮겨진다. 절대 경로를 문서에 박으면 그때 깨진다.

## Goals / Non-Goals

**Goals:**
- 스킬 문서 하나로 링크 걸기 / 풀기 / 상태 보기 세 가지를 다 할 수 있게 한다.
- 어떤 실패에서도 **원래 것을 잃지 않는다.** 못 하면 멈추고 사실을 말한다.
- 복사 방식(`install.sh`)과 링크 방식(이 스킬)이 서로를 가리키게 하되, 절차 본문은
  각각 한 곳에만 둔다.
- 확인된 것과 확인되지 않은 것을 갈라 적는다.

**Non-Goals:**
- 이 저장소(`init-SDD`) 자신에게 링크를 실제로 거는 것. proposal이 범위 밖으로 뺐다.
- `install.sh`의 복사 동작 변경. 안내 한 줄만 더한다.
- `install.sh`의 글롭 유출 수정 (아래 "Risks"의 R3 — 후속 change로 제안한다).
- 개인 저장소를 원격(GitHub 등)에 올리는 것. `git init`과 최초 커밋까지만 한다.

## Decisions

### D1. 스킬은 절차 세 갈래를 한 문서에 담는다 — 걸기 / 풀기 / 보기

한 문서 안에 `## 걸기`, `## 풀기`, `## 상태 보기` 세 절을 둔다. 사용자가 "연결해줘",
"풀어줘", "지금 연결돼 있어?"라고 말하면 해당 절로 간다.

*대안*: 스킬 세 개로 쪼갠다 → 버렸다. 세 절차가 같은 경로 해석·같은 표를 공유해서,
쪼개면 그 표가 세 벌이 된다. 이 저장소에서 사본이 갈라지는 것이 가장 나쁜 고장이다.

### D2. 세 경로를 실행 시점에 알아낸다 — 하나도 박지 않는다

| 이름 | 무엇 | 알아내는 법 |
|---|---|---|
| 원본 | 이 init-SDD 복제본 | 이 `SKILL.md`가 있는 위치에서 위로 올라가며 `install.sh`와 `CLAUDE.md`가 **함께** 있는 디렉터리를 찾는다. 못 찾으면 사용자에게 묻는다 |
| 대상 | SDD를 얹을 공유 프로젝트 | 기본값은 현재 작업 디렉터리. 사용자에게 확인한다 |
| 개인 | 개인 agentic 저장소 | 기본값 `~/work-space/agentic`을 **권하되** 실행 시점에 사용자에게 확인한다 |

Claude Code는 스킬을 부를 때 그 스킬의 기준 디렉터리를 알려 준다. 그래서 원본은 스스로
찾을 수 있다. `install.sh` 하나만으로 판단하지 않고 `CLAUDE.md`까지 함께 보는 이유:
조각을 뽑을 원본이 실제로 거기 있어야 하기 때문이다.

*대안*: 원본 경로를 사용자에게 매번 묻는다 → 버렸다. 스킬이 자기 위치를 알 수 있는데 묻는
것은 쓰는 사람을 번거롭게 한다. 못 찾을 때만 묻는다.

### D3. `CLAUDE.md`는 추적 여부로 갈라지고, 갈래를 먼저 판정한다

`.git/info/exclude`는 **추적되지 않는 파일만** 막는다. 이미 커밋된 `CLAUDE.md`에는 전혀
통하지 않는다. 그래서 먼저 판정한다:

```
git -C <대상> ls-files --error-unmatch CLAUDE.md   # 종료코드 0이면 추적 중
```

| 판정 | 수단 | 되돌리는 법 |
|---|---|---|
| 추적 안 됨 (또는 파일이 없음) | `.git/info/exclude`에 `CLAUDE.md` 한 줄 | 그 줄을 지운다 |
| 추적 중 | `git update-index --skip-worktree CLAUDE.md` | `--no-skip-worktree` |

**`.gitignore`는 절대 고치지 않는다.** 추적되는 공유 파일이라, 고치면 그 변경 자체가
커밋 대상이 된다. 개인 설정을 숨기려다 공유 저장소를 바꾸는 셈이다.

`skip-worktree`의 함정은 크다: 팀원이 `CLAUDE.md`를 고쳐 push하면 그 변경을 못 받는다.
pull이 막히거나 조용히 건너뛴다. 그래서 문서에 이 순서를 넣는다.

```
1) git update-index --no-skip-worktree CLAUDE.md
2) 마커 구획을 떼어 따로 보관 (또는 git stash)
3) git pull
4) 마커 구획을 다시 끝에 붙인다
5) git update-index --skip-worktree CLAUDE.md
```

*대안*: `assume-unchanged` → 버렸다. 그건 "성능을 위해 안 봐도 된다"는 힌트여서 git이
언제든 무시할 수 있다. 로컬 변경을 지키는 용도로는 `skip-worktree`가 맞다.

### D4. 조각은 원본 마커 구획에서 뽑고, 비면 멈춘다

`install.sh:91`과 같은 방식을 쓴다.

```
sed -n '/<!-- init-SDD:begin -->/,/<!-- init-SDD:end -->/p' "<원본>/CLAUDE.md"
```

조각 문구를 스킬 문서에 베껴 넣지 않는다. 뽑은 값이 비면 **멈춘다** — `install.sh:93`이
이미 그 안전장치를 갖고 있고, 이유가 같다. 빈 값을 붙이면 "성공했다"고 말하면서 아무
지시문도 안 들어가고, 사용자는 파이프라인이 왜 안 도는지 알 수 없게 된다.

대상 `CLAUDE.md`에 넣을지는 `install.sh:96-112`와 같은 세 갈래로 판정한다:
마커가 있으면 건너뛰고, 마커도 옛 낱말도 없으면 끝에 덧붙이고, 마커는 없는데 옛 낱말이
있으면 **넣지 않고 사실만 알린다.** 같은 판정을 두 곳에 서술하지 않기 위해 스킬 문서는
이 세 갈래를 표 한 개로 짧게 적고 근거를 메인 spec에 넘긴다.

붙이고 떼는 것은 **임시 파일에 새로 쓴 뒤 옮기는 방식**으로 한다. `sed -i`를 쓰지 않는다.
이 저장소에서 전체 재작성으로 마크다운이 망가진 사고가 있었고, 남의 프로젝트 파일에는
더 조심해야 한다.

### D5. 링크는 네 개만 걸고, `.claude/skills/`는 실제 디렉터리로 남긴다

```
<대상>/.claude/agents                  -> <개인>/<프로젝트>/agents
<대상>/.claude/skills/orchestra        -> <개인>/<프로젝트>/skills/orchestra
<대상>/.claude/skills/agent-model-tier -> <개인>/<프로젝트>/skills/agent-model-tier
<대상>/.claude/settings.json           -> <개인>/<프로젝트>/settings.json
```

`.claude/`를 통째로 링크하면 `openspec init`이 깐 `openspec-*` 6개와 `commands/opsx/`까지
개인 저장소로 끌려간다. 그것들은 사용자의 CLI 버전에 맞춰 깔린 물건이라 개인 저장소가
들고 다닐 것이 아니다. `.claude/skills/`도 통째로 링크하면 같은 일이 일어난다. 그래서
`skills/` 자체는 실제 디렉터리로 두고 그 안의 두 개만 링크한다.

링크는 **절대 경로**로 만든다. 상대 경로 링크는 대상 프로젝트가 옮겨지면 끊기지만, 절대
경로는 개인 저장소가 옮겨질 때만 끊긴다. 개인 저장소는 사용자가 한 번 정하는 것이라 더 안정적이다.

개인 저장소에 아직 내용이 없으면 원본에서 `cp -R`로 **한 번** 채운다(초기 이관). 그 뒤로는
개인 저장소가 원본이고, 다른 프로젝트도 같은 것을 가리킨다.

### D6. 프로젝트별 디렉터리 이름 — 기본은 폴더 이름, 짝을 파일에 적어 둔다

기본 이름은 대상 프로젝트 디렉터리의 이름(예: `init-SDD`)이다. 이름이 겹치는 경우를 위해
각 프로젝트별 디렉터리 안에 짝을 적은 작은 파일을 둔다.

```
<개인>/<프로젝트>/.init-sdd-target      # 안에 대상 프로젝트의 절대 경로 한 줄
```

| 같은 이름 디렉터리가 있을 때 | 무엇을 하는가 |
|---|---|
| `.init-sdd-target`이 지금 대상과 같다 | 그것을 다시 쓴다 (재실행·다른 컴퓨터에서 복원) |
| 다르다 | **멈추고 다른 이름을 묻는다** |
| `.init-sdd-target`이 없다 | **멈추고 사용자에게 확인한다** (사람이 손으로 만든 것일 수 있다) |

*대안*: 이름에 경로 해시를 붙여 자동으로 갈라 놓는다 → 버렸다. 사람이 개인 저장소를
직접 열어 파일을 고칠 물건인데, `init-SDD-a3f9c1` 같은 이름은 어느 프로젝트인지 알 수 없다.
이름은 사람이 읽는 것으로 두고, 짝은 파일로 확인한다.

### D7. 자리가 비어 있지 않으면 — 추적 중이면 무조건 멈춘다

| 그 자리의 상태 | 판정 방법 | 무엇을 하는가 |
|---|---|---|
| 없다 | `[[ ! -e p && ! -L p ]]` | 링크를 만든다 |
| 이 개인 저장소를 가리키는 링크 | `readlink p` 비교 | 이미 걸려 있다. 그대로 둔다 |
| 다른 곳을 가리키는 링크 | 같음 | **멈추고 어디를 가리키는지 알린다** |
| 실제 파일·디렉터리, git이 **추적 중** | `git ls-files -- <경로>`에 결과가 있다 | **멈추고 보고한다. 옮기지 않는다** |
| 실제 파일·디렉터리, **미추적** | 위가 비어 있다 | 알린 뒤, 사용자가 명시적으로 그러라고 하면 `<경로>.init-sdd-backup-<시각>`으로 옮긴다 |

추적 중인 것을 스킬이 옮기면 공유 저장소에 **삭제로 나타난다.** 팀이 커밋해 둔
`.claude/agents/`를 옮기고 누군가 `git commit -a`를 하면 팀 전체가 그것을 잃는다.
그래서 추적 중이면 예외 없이 멈춘다. 멈출 때 다음에 할 수 있는 것을 함께 알린다:
(a) 그 내용을 개인 저장소로 옮기고 다시 돌린다 (b) 복사 방식(`install.sh`)을 그대로 쓴다.

`-e`가 아니라 `-e` **와** `-L`을 같이 보는 이유: 끊긴 링크는 `-e`가 거짓이다(아래 R1의
실측). `-L`을 안 보면 끊긴 링크가 "없다"로 판정되어 그 위에 다시 링크를 만들려다 실패한다.

### D8. 링크가 공유 저장소 git에 새지 않게 `.git/info/exclude`를 쓴다

만든 링크는 공유 저장소에서 보면 미추적 파일이다. **실측**(아래 R2)에서 `.claude/agents`가
심볼릭 링크일 때 `git status --porcelain`이 `?? .claude/`를 냈고, `.git/info/exclude`에
경로를 적으면 조용해졌다. 링크는 추적되지 않는 파일이라 exclude가 통한다 —
`CLAUDE.md`(D3)와 다른 점이 여기다.

exclude에 적을 때 스킬이 적은 줄임을 알 수 있게 표시를 둘러싼다. 풀 때 그 표시 사이만
지우면 사용자가 원래 적어 둔 줄(예: 이 저장소의 `docs/`)을 건드리지 않는다.

```
# init-sdd:begin
.claude/agents
.claude/skills/orchestra
.claude/skills/agent-model-tier
.claude/settings.json
# init-sdd:end
```

### D9. 링크가 에이전트로 로드되는지는 확인되지 않았다 — 그대로 적는다

서브에이전트는 새 Claude Code 세션을 띄울 수 없다. 그래서 **확인할 수 있는 것과 없는 것을
갈라 놓는다.**

| 확인할 수 있는 것 (worker가 임시 프로젝트에서 실측한다) | 확인할 수 없는 것 |
|---|---|
| 링크가 만들어지는지, 절대 경로로 걸리는지 | Claude Code가 링크된 `.claude/agents/`를 **에이전트로 로드하는지** |
| 셸 글롭(`.claude/agents/*.md`)과 `cat`이 링크를 통과하는지 | 링크된 `.claude/skills/orchestra/`가 스킬 목록에 뜨는지 |
| `git status`가 조용한지, exclude가 통하는지 | |
| 풀었을 때 `git status`와 파일이 원래대로인지 | |

그래서 스킬의 **마지막 단계는 사용자에게 넘긴다**: "새 Claude Code 세션을 열고, 에이전트
목록과 스킬 목록에 실제로 잡히는지 확인해라." 안 잡혔을 때의 길도 문서에 둔다.

```
링크를 푼다 → 개인 저장소에서 cp -R 로 복사한다 → 복사된 경로도 .git/info/exclude 에 적는다
```

복사로 떨어져도 **개인 파일이 공유 저장소에 새지 않는 것은 지켜진다** (exclude가 미추적
복사물에는 통한다). 이 길이 없으면 사용자는 링크만 걸어 놓고 아무것도 안 도는 상태를 모른다.

### D10. `install.sh`는 한 줄, `README.md`는 한 절 — 절차 본문은 각자 한 곳에만

사용자 결정 1의 "둘이 서로를 가리켜야 한다"를 이렇게 푼다.

| 파일 | 무엇을 더하는가 |
|---|---|
| `README.md` | `## 설치` 맨 앞에 "먼저 고른다 — 복사 방식인가 링크 방식인가" 표 한 개. **고르는 안내의 본문은 여기 한 곳** |
| `install.sh` | 끝의 "다음 할 일" 안내에 링크 방식도 있다는 **한 줄** (`say` 한 줄) |
| `init-sdd/SKILL.md` | 자신이 링크 방식임을 밝히고 고르는 안내가 있는 곳(`README.md`)을 가리킨다 |

메인 spec에 이미 "설치 안내는 README 한 곳에만 있어야 한다"가 있다. 고르는 안내를 세 곳에
서술하면 그 요구사항을 깨고, 이 저장소가 두 번 겪은 고장(사본이 갈라지는 것)을 세 번째로
반복한다. 그래서 `install.sh`와 스킬 문서에는 **가리키는 말만** 둔다.

이 때문에 `distribution/sdd-install-script`에 요구사항 하나를 **ADDED**한다. MODIFIED가
아닌 이유: 기존 요구사항(제품 5종, 조각 원본 한 벌, 덮어쓰기 금지)의 동작은 하나도
바뀌지 않고 새 관심사가 얹히는 것뿐이다. OpenSpec 지시문도 "기존 동작을 바꾸지 않고
관심사를 더할 때는 ADDED를 쓰라"고 한다.

### D11. frontmatter는 `name`과 `description`만 — `allowed-tools`를 넣지 않는다

openspec 공식 스킬 6개는 `allowed-tools: Bash(openspec:*)`를 선언해서, 부르면 그 스킬이
도는 동안 쓸 수 있는 도구가 셸 명령 하나로 좁혀진다. 이 저장소의 에이전트 지시문들이
"그 스킬을 부르지 말고 읽어서 따르라"고 적어 둔 이유가 그것이다. `init-sdd`는 파일을
만들고 링크를 걸고 git 명령을 돌려야 해서 좁히면 아무것도 못 한다.

`description`은 같은 저장소의 `orchestra`·`agent-model-tier`와 같은 형식으로 쓴다:
무엇을 하는 스킬인지 한 문장 + 사용자가 실제로 할 만한 말을 따옴표로 여러 개.

## Risks / Trade-offs

**R1. 끊긴 링크가 걸린 프로젝트에서 `install.sh`를 돌리면 install이 중간에 죽거나 엉뚱한
곳에 파일을 만든다 (실측함)**

`copy_if_absent`는 `[[ -e "$d" ]]`로 판단한다. 이 저장소가 도는 macOS에서 재보니:

| 상황 | `[[ -e ]]` | `cp` 결과 |
|---|---|---|
| 살아 있는 링크 | **참** | 복사 안 함 → `[있음, 건너뜀]`. 안전하다 |
| 끊긴 **디렉터리** 링크 | 거짓 | `cp: ...: File exists`, 종료코드 1 |
| 끊긴 **파일** 링크, 가리키는 곳의 부모가 없다 | 거짓 | `cp: ...: No such file or directory`, 종료코드 1 |
| 끊긴 **파일** 링크, 부모는 있다 | 거짓 | **종료코드 0. 링크를 따라가 개인 저장소 자리에 파일을 만든다** |

`install.sh`는 `set -euo pipefail`이라 종료코드 1이면 **거기서 죽는다** — 절반만 깔린 채
끝난다. 마지막 줄이 더 나쁘다: `.claude/settings.json` 링크가 끊긴 상태(개인 저장소를 아직
복제하지 않은 새 컴퓨터)에서 조용히 성공하면서, 공유 프로젝트의 설정이 개인 저장소 자리에
가서 앉는다.

→ **완화**: (a) 스킬 문서에 "링크가 걸린 프로젝트에서 `install.sh`를 돌리기 전에 개인
저장소가 제자리에 있는지 확인해라"를 적는다. (b) 상태 보기가 **끊긴 링크를 따로**
알려 준다(D 상태표의 네 번째 갈래). `install.sh` 자체를 고쳐 `-L`을 함께 보게 하는 것은
복사 동작 변경이라 이번 범위 밖이다 — R3과 함께 후속으로 제안한다.

**R2. 링크가 공유 저장소에 커밋될 수 있다 → D8로 막았고 실측했다**

임시 git 저장소에서 `.claude/agents`를 심볼릭 링크로 만들었더니
`git status --porcelain`이 `?? .claude/`를 냈다. `.git/info/exclude`에 경로를 적으니
출력이 비었다. exclude가 통하는 것은 링크가 미추적 파일이기 때문이다.

**R3. `install.sh`의 글롭이 개인 파일을 대상 프로젝트로 흘린다 (실물로 확인됨)**

`install.sh:73`이 `for f in "$SRC"/.claude/agents/*.md`로 돈다. **git이 아니라 디렉터리를
본다.** 지금 이 저장소 `.claude/agents/`에는 미추적 개인 파일 `agy.md`가 있어서 파일이
**8개**이고, `install.sh:120`은 "7이어야 한다"고 적혀 있다. 커밋하지 않아도 복사 방식으로는
대상 프로젝트에 딸려간다.

링크 방식에서는 이 길이 **저절로 닫힌다.** 개인 파일은 개인 저장소 안에만 있고 공유
프로젝트 트리에는 링크 한 개만 놓인다. 글롭이 훑을 개인 파일이 그 트리에 없다.

→ 이번 change에서는 고치지 않는다. 고치려면 복사 대상을 git 추적 파일로 제한하거나
이름 7개를 명시해야 하고, 둘 다 메인 spec `distribution/sdd-install-script`의 "제품 5종"
요구사항을 **바꾸는** 일이다(MODIFIED 델타가 필요하다). 사용자가 "요구사항을 늘리지 마라"
고 했으므로 **후속 change로 제안한다.**

**R4. 링크가 에이전트로 로드되지 않을 수 있다 → D9의 복사 대체 경로**

확인되지 않은 것이 이 설계의 가장 큰 미지다. 안 되면 링크 방식의 값은 "개인 파일을 공유
저장소에 안 남기는 것"만 남고 복사로 떨어진다. 그래도 그 값은 exclude로 지켜진다.

**R5. `skip-worktree`를 걸어 둔 채 팀의 `CLAUDE.md` 변경을 놓칠 수 있다**

→ 완화: D3의 해제 → pull → 재적용을 문서에 넣고, 상태 보기가 지금 걸려 있는지 보여준다.
근본적으로 없앨 수는 없다. 추적되는 파일을 로컬에서만 다르게 두려면 이 수단밖에 없다.

**R6. 이 저장소 자신에게 적용할 때는 조심해야 한다**

이 저장소는 `docs/`를 `.git/info/exclude`로 빼 두었다. D8이 같은 파일에 줄을 더한다.
표시(`# init-sdd:begin` ~ `# init-sdd:end`) 사이만 다루면 `docs/` 줄은 안전하다. 다만
이 저장소 자신에게 적용하는 것은 proposal이 범위 밖으로 뺐다 — 스킬을 만드는 것까지다.

## Migration Plan

새 문서를 더하고 기존 두 파일에 안내를 더하는 것뿐이다. 되돌리기는
`git revert` 한 번이면 된다. 대상 프로젝트에 이미 깔린 것에는 영향이 없다 — 이 change는
어떤 프로젝트에도 링크를 걸지 않는다.

## Open Questions

- 개인 저장소를 원격에 올릴지(그러면 다른 컴퓨터에서 복제해 링크만 다시 걸면 된다)는
  사용자가 나중에 정해도 된다. 스킬은 `git init`과 최초 커밋까지만 하고, 원격 설정은
  "원하면 직접 하라"는 한 줄로 남긴다. 이 답이 무엇이든 요구사항과 작업 목록은 바뀌지 않는다.
