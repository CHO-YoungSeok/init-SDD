# tasks — convert-to-plugin

채택: 상위 change `plugin-lite-sdd-distribution` decision.md 1안(플러그인 전면 전환). 이 change는 analyzer 생략 경로이고 기준은 proposal의 받아들일 조건 + specs 델타다.
핵심 결정:
- 저장소 루트 = 플러그인 `sdd`. 에이전트는 `sdd:<이름>`으로 부르고, `not found`면 접두사 없이 다시 부른다(기존 설치본 대비, orchestra·sdd-rules에 한 번씩).
- 지시문의 openspec 명령은 `sdd-openspec`(고정 1.14.1 래퍼). 없으면 `openspec`(sdd-rules 대체 규칙).
- 파일 이동(`git mv`)은 내용 수정이 다 끝난 뒤 묶음 8에서만 한다. 그 전까지 모든 수정은 **이동 전 경로**(`.claude/agents/`, `.claude/skills/...`)에서 한다.
- SessionStart 훅은 표식 `openspec/.sdd`가 있을 때만 켜진다(`/sdd:init`이 만든다, 이 저장소도 갖는다). 메인 spec 경로는 sync 때 플러그인 루트 기준 상대 경로로 치환한다(D12).
- 이 저장소의 프로젝트 지침 파일은 루트 `CLAUDE.md`가 아니라 `.claude/CLAUDE.md`다(루트에 두면 `validate --strict` 실패 — design E7·D15). 원본 쪽 경로만 바뀌고 대상 프로젝트의 `CLAUDE.md`는 그대로다.
자세한 내용은 design.md(D1~D15)를 본다.

**순서 의존:** 1 → (2, 3, 4, 5, 6, 7 병렬) → (6.4, 6.5, 6.6, 7.5 병렬 — 2026-10-09 추가분, 8 전에) → 8.1(정리 모드) → 8.2 → 8.3 → 9(9.16 포함) → 9.15(정리 모드, 해당할 때만).
- 묶음 2~7은 서로 파일이 겹치지 않는다. 담당 파일 밖은 만지지 않는다.
- `verification.md`는 묶음 1과 9만 쓴다. 다른 묶음은 결과를 worker 보고서에 적는다.
- 묶음 1에서 멈춤 조건에 걸리면 이후 묶음을 시작하지 않는다.
- **삭제는 정리 모드 worker만 한다**(worker.md "삭제는 프롬프트가 경로를 글자 그대로 지정한 정리 모드만"). 8.1과 9.15는 오케스트레이터가
  `모드: 정리` worker를 따로 부르고 삭제 경로를 프롬프트에 글자 그대로 싣는다. 체크박스는 다음에 부르는 정식 모드 worker가 확인 명령을 다시 돌려 체크한다.
- **외부 호출 허용:** 묶음 1·2·9의 `claude -p`, `claude plugin validate/marketplace/install/list/eval`, `npx`·`sdd-openspec`의 npm 내려받기,
  로컬 경로 마켓플레이스 등록은 이 change가 허용한 작업이다(sdd-rules "외부 서비스 호출"의 승인 근거). 오케스트레이터는 그 묶음 worker 프롬프트에
  `외부 호출: 허용 (tasks 머리말 범위)` 한 줄을 싣는다. 마켓플레이스·설치 시험은 격리 `CLAUDE_CONFIG_DIR`에서만 한다.
  `claude plugin eval`은 `--max-cost-usd 0.05 --no-publish`와 저장소 밖 `--output-dir`·`--json`·`--report`로만 돌린다. 전역 설치와 사용자 `~/.claude` 변경은 허용하지 않는다.
