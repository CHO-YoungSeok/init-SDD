# distribution/init-sdd-skill Specification

## Purpose

개인 agentic 설정(서브에이전트 7개, 지휘 스킬, 모델 등급 스킬, 권한 설정)을 별도의 개인 git
저장소에 두고, 공유 프로젝트의 `.claude/` 안에서는 그것을 심볼릭 링크로 가리키게 해 주는
`init-sdd` 스킬의 계약을 정한다. 링크를 걸고 푸는 것이 양방향이어야 하고, 공유 저장소가
원래 상태로 되돌아와야 하며, 대상 프로젝트에 이미 있는 것을 잃지 않아야 한다.

## Requirements

### Requirement: 스킬은 이 저장소에 있고 도구를 좁혀서는 안 된다

`init-sdd` 스킬 문서는 이 저장소의 `.claude/skills/init-sdd/SKILL.md`에 있어야 한다(SHALL).
이 스킬의 일 중 하나가 **개인 저장소를 만들어 주는 것**이라서, 개인 저장소가 아직 없는
상태에서도 손에 잡혀야 한다. 개인 저장소 쪽에 두면 스킬을 쓰려면 개인 저장소가 있어야 하고
개인 저장소를 만들려면 스킬이 있어야 하는 순환이 된다(사용자 결정).

frontmatter에는 `name`과 `description`만 있어야 하며(SHALL), `allowed-tools`를 넣어서는 안
된다(MUST NOT). 이 스킬은 파일을 만들고 링크를 걸고 git 명령을 돌려야 한다. openspec 공식
스킬 6개가 `allowed-tools: Bash(openspec:*)`로 도구를 하나로 좁혀서 파일을 못 쓰게 되는
일이 실제로 일어났다.

`description`에는 사용자가 실제로 할 만한 **발동 신호(부르는 말)**가 들어 있어야 한다(MUST).
같은 저장소의 `orchestra`와 `agent-model-tier` 스킬이 그렇게 되어 있다. 신호가 없으면
스킬이 있어도 불리지 않는다.

#### Scenario: 스킬 파일이 제 위치에 있고 마크다운이 온전하다

- **WHEN** `.claude/skills/init-sdd/SKILL.md`를 읽는다
- **THEN** 파일이 있고, `---`로 둘러싼 frontmatter가 온전하며 `name: init-sdd`가 있다
- **AND** 코드펜스(```) 개수가 짝수다

#### Scenario: 도구를 좁히지 않았다

- **WHEN** `.claude/skills/init-sdd/SKILL.md`의 frontmatter를 읽는다
- **THEN** `allowed-tools` 키가 없다

#### Scenario: 부르는 말이 적혀 있다

- **WHEN** `description` 값을 읽는다
- **THEN** 사용자가 쓸 만한 말이 여러 개 들어 있다 (예: "링크로 연결", "개인 저장소로
  분리", "연결 풀기", "지금 연결돼 있어?")
- **AND** 이 스킬이 무엇을 하는 스킬인지 한 문장으로 알 수 있다

### Requirement: 개인 소유와 openspec CLI 소유를 갈라서 링크해야 한다

스킬은 `.claude/`를 통째로 링크해서는 안 된다(MUST NOT). 그 안에는 소유자가 다른 것이
섞여 있다. **개인 소유만 골라서** 링크해야 한다(SHALL).

링크 대상은 정확히 네 개다(SHALL):

| 경로 | 종류 |
|---|---|
| `.claude/agents/` | 디렉터리 |
| `.claude/skills/orchestra/` | 디렉터리 |
| `.claude/skills/agent-model-tier/` | 디렉터리 |
| `.claude/settings.json` | 파일 |

`.claude/skills/openspec-*`(6개)와 `.claude/commands/opsx/`는 링크 대상에서 **제외해야
한다**(MUST NOT link). `openspec init --tools claude`가 사용자의 CLI 버전에 맞는 것을 대상
프로젝트에 직접 깔아 주는 물건이다.

`.claude/skills/` 자체는 **실제 디렉터리로 남아야 하며**(SHALL), 그 안의 두 개만 링크가
된다. `.claude/settings.local.json`은 만들지도 고치지도 지우지도 않아야 한다(MUST NOT) —
개인 로컬 설정이고 이미 추적 제외 대상이다.

#### Scenario: 문서가 소유를 갈라 적는다

- **WHEN** 스킬 문서에서 링크 대상 목록을 읽는다
- **THEN** 위 네 개가 링크 대상으로 적혀 있다
- **AND** `openspec-*` 6개와 `commands/opsx/`가 **링크하지 않는 것**으로 적혀 있고 그 이유
  (openspec CLI가 깐다)가 함께 적혀 있다
- **AND** `.claude/` 통째 링크를 하지 말라는 말이 명시돼 있다
- **AND** `settings.local.json`은 건드리지 않는다고 적혀 있다

#### Scenario: 링크를 걸어도 openspec 스킬이 그대로 남는다

- **WHEN** 임시 프로젝트에 절차를 돌린 뒤 `.claude/skills/`를 본다
- **THEN** `.claude/skills/`는 심볼릭 링크가 아닌 실제 디렉터리다
- **AND** `openspec-*` 스킬 디렉터리들이 실제 디렉터리로 그대로 있다
- **AND** `orchestra`와 `agent-model-tier`만 심볼릭 링크다

### Requirement: 경로를 하드코딩해서는 안 된다

스킬 문서는 절대 경로를 하드코딩해서는 안 된다(MUST NOT). 다음 세 경로를 **실행 시점에**
알아내야 한다(SHALL):

- **원본 저장소** (이 init-SDD 복제본): 스킬 자신의 위치에서 위로 올라가 `install.sh`와
  `CLAUDE.md`가 함께 있는 디렉터리를 찾는다. 찾지 못하면 사용자에게 묻는다.
- **대상 프로젝트**: 기본값은 현재 작업 디렉터리. 사용자에게 확인한다.
- **개인 agentic 저장소**: 기본값 `~/work-space/agentic`을 **권하되**, 실행 시점에 사용자
  에게 확인한다. 사용자가 다른 경로를 주면 그것을 쓴다.

특히 이 저장소의 현재 절대 경로(`/Users/0stone_1004/orca/projects/init-SDD`)가 문서 어디에도
있어서는 안 된다(MUST NOT). 이 저장소는 곧 다른 경로로 옮겨질 예정이고, 박아 두면 그때 깨진다.

#### Scenario: 저장소 절대 경로가 문서에 없다

- **WHEN** 스킬 문서 전체를 `/Users/`로 검색한다
- **THEN** 아무것도 나오지 않는다

#### Scenario: 개인 저장소 경로를 실행 시점에 확인한다

- **WHEN** 스킬 문서에서 개인 저장소 경로를 정하는 부분을 읽는다
- **THEN** `~/work-space/agentic`이 **기본값·권함**으로 제시된다
- **AND** 실행 시점에 사용자에게 확인하라고 적혀 있고, 사용자가 준 경로를 쓴다고 적혀 있다
- **AND** 그 경로가 그 자리 말고 다른 절차 단계에 다시 박혀 있지 않다 (변수로 다룬다)

#### Scenario: 원본 저장소를 스스로 찾는다

- **WHEN** 스킬 문서에서 원본 저장소를 정하는 부분을 읽는다
- **THEN** 스킬 자신의 위치를 기준으로 위로 올라가 `install.sh`와 `CLAUDE.md`가 함께 있는
  디렉터리를 찾는 방법이 적혀 있다
- **AND** 찾지 못했을 때 사용자에게 묻는 길이 적혀 있다

### Requirement: 개인 저장소가 없으면 만들고, 프로젝트별 디렉터리 이름이 겹치면 물어야 한다

개인 저장소 경로에 git 저장소가 없으면 스킬이 만들어야 한다(SHALL): 디렉터리를 만들고
`git init`을 하고 최초 커밋을 만든다. 이미 git 저장소가 있으면 **그것을 쓰고 새로 만들지
않아야 한다**(MUST NOT re-init).

개인 저장소 안에는 프로젝트별 디렉터리를 둔다. 이름의 기본값은 **대상 프로젝트 디렉터리의
이름**이어야 한다(SHALL). 이름이 겹칠 수 있으므로, 각 프로젝트별 디렉터리는 자기가 어느
대상 프로젝트를 위한 것인지 **기록해 두어야 한다**(SHALL). 같은 이름의 디렉터리가 이미
있으면:

| 상황 | 무엇을 하는가 |
|---|---|
| 기록된 대상이 지금 대상과 같다 | 그 디렉터리를 다시 쓴다 |
| 기록된 대상이 다르다 (다른 프로젝트인데 이름만 같다) | **멈추고 다른 이름을 묻는다** |
| 기록이 없다 (사람이 손으로 만든 디렉터리) | **멈추고 사용자에게 확인한다** |

이름이 겹칠 때 짐작으로 덮어써서는 안 된다(MUST NOT). 다른 프로젝트의 에이전트 설정을
잃는다.

#### Scenario: 개인 저장소가 아직 없다

- **WHEN** 사용자가 준 개인 저장소 경로에 아무것도 없는 상태로 절차를 돌린다
- **THEN** 디렉터리가 만들어지고 `git init`이 돌아가고 최초 커밋이 생긴다
- **AND** 대상 프로젝트를 위한 프로젝트별 디렉터리가 그 안에 생긴다

#### Scenario: 개인 저장소가 이미 있다

- **WHEN** 이미 git 저장소인 경로를 개인 저장소로 주고 절차를 돌린다
- **THEN** `git init`을 다시 돌리지 않는다
- **AND** 기존 커밋 이력과 기존 프로젝트별 디렉터리가 그대로 남아 있다

#### Scenario: 이름만 같은 다른 프로젝트가 이미 있다

- **WHEN** 개인 저장소에 같은 이름의 프로젝트별 디렉터리가 있고, 그 기록된 대상이 지금
  대상과 다르다
- **THEN** 멈추고 그 사실을 알리고 다른 이름을 묻는다
- **AND** 기존 디렉터리의 내용이 하나도 바뀌지 않는다

### Requirement: 대상 프로젝트에 이미 있는 것을 잃어서는 안 된다

링크를 걸 자리에 이미 무엇이 있으면, **원래 것을 잃지 않는 것이 링크를 거는 것보다
우선한다**(SHALL). 상황별로 이렇게 다뤄야 한다(MUST):

| 그 자리의 상태 | 무엇을 하는가 |
|---|---|
| 없다 | 링크를 만든다 |
| 이미 이 개인 저장소를 가리키는 링크다 | 이미 걸려 있다. 그대로 둔다 |
| 다른 곳을 가리키는 링크다 | **멈추고 어디를 가리키는지 알린다** |
| 실제 파일·디렉터리인데 공유 저장소 git이 **추적 중**이다 | **멈추고 보고한다.** 스킬이 절대 옮기지 않는다 |
| 실제 파일·디렉터리인데 **미추적**이다 | 멈추고 알린 뒤, 사용자가 명시적으로 그러라고 하면 백업 이름으로 비켜 둔다 |

추적 중인 파일을 스킬이 옮겨서는 안 된다(MUST NOT). 팀이 커밋해 둔 설정을 옮기면 공유
저장소에 삭제로 나타나고, 그것이 실수로 커밋될 수 있다. 미추적 파일을 비켜 둘 때도 지우지
않아야 하며(MUST NOT delete), 언제 만든 백업인지 알 수 있는 이름을 붙여야 한다(SHALL).

멈출 때는 사용자가 다음에 무엇을 할 수 있는지 **함께 알려야 한다**(MUST): 기존 내용을 개인
저장소로 옮긴 뒤 다시 돌리기, 또는 복사 방식(`install.sh`)을 그대로 쓰기.

#### Scenario: 팀이 커밋해 둔 에이전트 디렉터리가 이미 있다

- **WHEN** `.claude/agents/`가 실제 디렉터리로 있고 공유 저장소 git이 추적 중인 프로젝트에
  절차를 돌린다
- **THEN** 멈추고 그 사실을 알린다
- **AND** 그 디렉터리의 파일이 하나도 바뀌거나 사라지지 않는다
- **AND** `git status`가 실행 전과 같다
- **AND** 다음에 할 수 있는 선택(개인 저장소로 옮기고 다시 돌리기 / 복사 방식 쓰기)을 알려 준다

#### Scenario: 미추적 개인 파일이 그 자리에 있다

- **WHEN** `.claude/agents/`가 있지만 git이 추적하지 않는 프로젝트에 절차를 돌린다
- **THEN** 그 사실을 알리고 사용자에게 확인을 받는다
- **AND** 확인을 받은 뒤에는 지우지 않고 언제 만든 것인지 알 수 있는 백업 이름으로 비켜 둔다
- **AND** 확인을 받지 못하면 아무것도 바꾸지 않는다

#### Scenario: 이미 걸려 있는 프로젝트에 다시 돌린다

- **WHEN** 이미 링크가 걸린 프로젝트에 절차를 다시 돌린다
- **THEN** 이미 걸려 있다고 알리고 링크를 다시 만들지 않는다
- **AND** 링크가 가리키는 곳이 바뀌지 않는다

### Requirement: CLAUDE.md 조각은 원본 한 벌에서 뽑아 붙여야 한다

스킬은 SDD 지시문 조각을 문서 안에 베껴 적어서는 안 된다(MUST NOT). 원본 저장소 `CLAUDE.md`의
마커 구획(`<!-- init-SDD:begin -->` ~ `<!-- init-SDD:end -->`)에서 **기계적으로 뽑아야
한다**(SHALL). `install.sh`가 이미 같은 방식을 쓰고 있고, 조각 원본이 저장소 전체에 한 벌인
것은 메인 spec `distribution/sdd-install-script`가 요구하는 것이다.

뽑은 조각이 비면 **멈춰야 한다**(MUST). 빈 값을 붙이면 "성공"이라고 말하면서 아무 지시문도
안 들어간다. `install.sh`가 이미 그 안전장치를 갖고 있다.

대상 프로젝트 `CLAUDE.md`가 이미 있으면 덮어쓰지 않고 **끝에 덧붙여야 한다**(SHALL). 마커
구획이 이미 있으면 두 번 넣지 않아야 한다(MUST NOT).

#### Scenario: 조각을 베끼지 않고 뽑는다

- **WHEN** 스킬 문서의 `CLAUDE.md` 처리 부분을 읽는다
- **THEN** 조각 본문(파이프라인 순서를 적은 `순서:` 줄 등)이 스킬 문서에 실려 있지 않다
- **AND** 마커 구획을 원본 `CLAUDE.md`에서 뽑아내는 명령이 있다

#### Scenario: 뽑은 조각이 비었다

- **WHEN** 원본 `CLAUDE.md`에 마커가 없거나 구획이 비어서 뽑기가 빈 값을 낸다
- **THEN** 멈추고 원본의 마커를 확인하라고 알린다
- **AND** 대상 프로젝트 `CLAUDE.md`가 바뀌지 않는다

#### Scenario: 조각이 두 번 들어가지 않는다

- **WHEN** 이미 마커 구획이 있는 `CLAUDE.md`에 절차를 다시 돌린다
- **THEN** 이미 들어가 있다고 알리고 넣지 않는다
- **AND** 마커 구획이 정확히 하나뿐이다

### Requirement: 추적 여부에 따라 CLAUDE.md를 로컬에만 두는 방법이 갈라져야 한다

대상 프로젝트 `CLAUDE.md`에 조각을 붙인 변경은 **공유 저장소 git에 들어가지 않아야
한다**(SHALL). 그 방법은 그 파일이 공유 저장소 git에 추적되는지에 따라 **두 갈래로 갈라야
한다**(MUST):

| `CLAUDE.md`의 상태 | 쓰는 수단 |
|---|---|
| 추적되지 않는다 (또는 아직 없다) | `.git/info/exclude`에 `CLAUDE.md`를 적는다 |
| 이미 추적된다 | `git update-index --skip-worktree CLAUDE.md` |

`.git/info/exclude`를 추적되는 파일에 쓰려 해서는 안 된다(MUST NOT). exclude는 **추적되지
않는 파일만** 막는다. 이미 커밋된 파일에는 전혀 통하지 않는다. 이것을 통한다고 적으면
사용자는 막혔다고 믿고 조각이 든 `CLAUDE.md`를 커밋한다.

공유 저장소의 `.gitignore`를 고쳐서는 안 된다(MUST NOT). 그 파일은 추적되는 공유 파일이라
고치면 그 변경 자체가 커밋 대상이 된다.

#### Scenario: 두 갈래가 문서에 갈라져 있다

- **WHEN** 스킬 문서의 `CLAUDE.md` 처리 부분을 읽는다
- **THEN** "추적 안 됨 → `.git/info/exclude`"와 "추적 됨 → `skip-worktree`"가 갈라져 있다
- **AND** 어느 쪽인지 알아내는 방법(예: `git ls-files --error-unmatch CLAUDE.md`)이 적혀 있다
- **AND** exclude는 추적되는 파일에 통하지 않는다는 사실이 적혀 있다

#### Scenario: 추적되는 CLAUDE.md에 조각을 붙였다

- **WHEN** `CLAUDE.md`가 이미 커밋된 임시 프로젝트에 절차를 돌린다
- **THEN** 파일에는 조각이 들어가 있다
- **AND** `git status`에 그 파일이 변경으로 나타나지 않는다
- **AND** `.gitignore`가 바뀌지 않았다

### Requirement: skip-worktree의 함정과 그 대처를 적어야 한다

`git update-index --skip-worktree`를 쓰면 **팀원이 그 파일을 고쳐 push한 변경을 받지
못한다**. pull이 막히거나 조용히 그 변경을 건너뛴다. 스킬 문서는 이 함정을 **명시해야
하고**(MUST), 다음 순서를 절차로 넣어야 한다(SHALL):

1. `git update-index --no-skip-worktree CLAUDE.md` (해제)
2. 조각 구획을 잠시 떼어 두거나 변경을 보관한다
3. `git pull`
4. 조각 구획을 다시 붙인다
5. `git update-index --skip-worktree CLAUDE.md` (재적용)

이 순서를 적지 않고 `skip-worktree`만 걸라고 하면, 사용자는 팀의 `CLAUDE.md` 변경을 영영
못 받으면서 그 사실조차 모른다.

#### Scenario: 해제 → pull → 재적용이 적혀 있다

- **WHEN** 스킬 문서에서 `skip-worktree`를 다루는 부분을 읽는다
- **THEN** 팀원의 변경을 못 받는다는 함정이 적혀 있다
- **AND** 해제 → pull → 재적용의 순서가 실행할 수 있는 명령과 함께 적혀 있다

### Requirement: 링크가 공유 저장소 git에 새어서는 안 된다

`.claude/` 안에 만든 심볼릭 링크는 공유 저장소 git에서 보면 **미추적 파일**이다.
그대로 두면 `git status`에 나타나고 `git add -A`에 딸려 커밋된다. 스킬은 만든 링크
경로를 대상 프로젝트 `.git/info/exclude`에 적어야 한다(SHALL). 링크는 추적되지 않는
파일이므로 exclude가 통한다.

절차를 마친 뒤 `git status`가 절차를 돌리기 전과 같아야 한다(SHALL). 링크를 걸었다는 사실이
공유 저장소 쪽에 드러나지 않는 것이 이 스킬의 목적이다.

#### Scenario: 링크를 걸어도 git status가 조용하다

- **WHEN** 깨끗한 임시 프로젝트에 절차를 돌린 뒤 `git status --porcelain`을 본다
- **THEN** 출력이 절차를 돌리기 전과 같다
- **AND** 만든 링크 경로가 `.git/info/exclude`에 적혀 있다

### Requirement: 걸었다 풀 수 있어야 하고, 풀면 원래 상태로 돌아와야 한다

스킬은 링크를 거는 절차와 **푸는 절차를 둘 다 가져야 한다**(SHALL). 푸는 절차는 다음을
전부 되돌려야 한다(MUST):

- 만든 심볼릭 링크 네 개를 없앤다 (링크만 없앤다 — 링크가 가리키던 개인 저장소의 내용은
  건드리지 않는다)
- `CLAUDE.md`의 마커 구획을 떼어 낸다
- `git update-index --no-skip-worktree CLAUDE.md`로 표시를 해제한다
- `.git/info/exclude`에 스킬이 적어 넣은 줄만 지운다 (사용자가 원래 적어 둔 줄은 그대로 둔다)

푼 뒤에는 공유 저장소가 절차를 돌리기 **전과 같아야 한다**(SHALL): 추적 파일 내용이 같고
`git status`가 같다. 개인 저장소의 내용은 지워지지 않아야 한다(MUST NOT) — 다른 프로젝트도
그것을 쓴다.

#### Scenario: 걸었다 풀면 제자리로 돌아온다

- **WHEN** 임시 프로젝트에 절차를 돌리고, 파일 목록과 `git status`를 기록한 뒤 푸는 절차를
  돌린다
- **THEN** 링크 네 개가 사라진다
- **AND** `CLAUDE.md`가 절차 전 내용과 같고 `skip-worktree` 표시가 해제돼 있다
- **AND** `.git/info/exclude`가 절차 전과 같다
- **AND** `git status`가 절차 전과 같다

#### Scenario: 풀어도 개인 저장소는 남는다

- **WHEN** 푸는 절차를 돌린 뒤 개인 저장소를 본다
- **THEN** 프로젝트별 디렉터리와 그 안의 파일이 그대로 있다
- **AND** 개인 저장소의 git 이력이 그대로 있다

### Requirement: 지금 걸려 있는지 알 수 있어야 한다

스킬은 현재 연결 상태를 보여주는 절차를 가져야 한다(SHALL). 다음을 모두 보여야 한다(MUST):

- 링크 대상 네 개 각각이 **링크됨(어디를 가리키는지) / 실제 파일·디렉터리 / 없음 /
  끊긴 링크** 중 무엇인지
- `CLAUDE.md`에 마커 구획이 있는지
- `CLAUDE.md`에 `skip-worktree` 표시가 걸려 있는지
- `.git/info/exclude`에 스킬이 적은 줄이 있는지

**끊긴 링크**(가리키는 곳이 없는 링크)를 따로 알려야 한다(MUST). 개인 저장소를 아직 복제하지
않은 새 컴퓨터에서 이 상태가 되고, 그 상태에서는 에이전트가 하나도 로드되지 않는데 링크는
걸려 있어서 겉으로는 정상처럼 보인다.

#### Scenario: 상태 확인이 네 갈래를 구분한다

- **WHEN** 상태 확인 절차를 읽는다
- **THEN** 링크됨·실제 파일·없음·끊긴 링크 네 갈래를 구분하는 방법이 적혀 있다
- **AND** `CLAUDE.md` 마커·`skip-worktree`·`.git/info/exclude`도 함께 확인한다

#### Scenario: 끊긴 링크를 잡아낸다

- **WHEN** 링크를 걸어 둔 뒤 개인 저장소 디렉터리 이름을 바꿔 링크를 끊고 상태 확인을 돌린다
- **THEN** 그 링크가 끊겼다고 알린다
- **AND** 개인 저장소를 복제·복구하거나 링크를 풀라고 알려 준다

### Requirement: 링크가 에이전트로 로드되는지는 사용자가 새 세션에서 확인해야 한다

심볼릭 링크로 놓인 `.claude/agents/`가 Claude Code에서 **실제로 에이전트로 로드되는지는
아직 확인되지 않았다.** 스킬 문서는 이 사실을 정직하게 적어야 하고(MUST), 마지막 단계로
**사용자가 새 Claude Code 세션을 열어 확인하는 절차를 두어야 한다**(SHALL).

서브에이전트는 새 Claude Code 세션을 띄울 수 없다. 실측으로 확인할 수 있는 것은 파일시스템과
git 수준까지다(링크가 만들어지는지, 셸 글롭과 `cat`이 링크를 통과하는지, `git status`가
조용한지). "에이전트로 로드되는지"는 그 밖이다. 확인되지 않은 것을 확인된 것처럼 적어서는
안 된다(MUST NOT).

로드되지 않을 경우를 대비해 **복사로 떨어지는 길**을 문서에 두어야 한다(SHALL): 링크를 풀고
개인 저장소에서 `cp -R`로 복사한 뒤, 복사된 경로도 `.git/info/exclude`에 적어 공유 저장소에
새지 않게 한다. 이 길이 없으면 사용자는 링크만 걸어 놓고 아무것도 안 도는 상태를 모른다.

#### Scenario: 실측 결과와 그 한계가 적혀 있다

- **WHEN** 스킬 문서(또는 이 change의 산출물)에서 링크 인식에 관한 부분을 읽는다
- **THEN** 파일시스템·git 수준에서 확인된 것과 확인되지 않은 것이 갈라져 적혀 있다
- **AND** "에이전트로 로드되는지"는 사용자가 새 세션에서 확인해야 한다고 적혀 있다

#### Scenario: 새 세션 확인이 마지막 단계에 있다

- **WHEN** 스킬 절차의 마지막 부분을 읽는다
- **THEN** 새 Claude Code 세션을 열라는 단계가 있다
- **AND** 에이전트와 스킬이 실제로 잡혔는지 확인하는 구체적인 방법이 적혀 있다
- **AND** 안 잡혔을 때 복사(`cp -R`)로 떨어지는 절차가 적혀 있고, 복사된 경로도
  `.git/info/exclude`에 넣으라고 적혀 있다

### Requirement: 복사 방식과 언제 무엇을 쓰는지 서로 가리켜야 한다

스킬 문서는 자신이 **링크 방식**이며 `install.sh`가 **복사 방식**이라는 것을 적어야
한다(SHALL). 그리고 **어떤 때 어느 것을 쓰는지**를 적어야 한다(MUST): 팀이 SDD 방식에
합의했으면 복사 방식, 개인이 자기 설정을 별도 git으로 관리하려면 링크 방식.

같은 절차를 두 곳에 서술해서는 안 된다(MUST NOT). 고르는 안내의 본문은 `README.md` 한 곳에
두고, 스킬 문서는 그것을 **가리켜야 한다**(SHALL). 같은 문구의 사본이 갈라지는 것이 이
저장소에서 가장 나쁜 고장이고, 이미 두 번 났다.

두 방식이 한 프로젝트에서 섞였을 때 무엇이 일어나는지도 적어야 한다(MUST):
`install.sh`의 `copy_if_absent`는 `[[ -e "$d" ]]`로 판단하므로 **살아 있는 링크는 "있음,
건너뜀"으로 처리된다**(덮어쓰지 않는다). 그러나 **끊긴 링크는 `-e`가 거짓이어서 복사가
일어나고, 복사가 링크를 따라가 엉뚱한 곳에 파일을 만들 수 있다.** 그래서 링크가 걸린
프로젝트에서 `install.sh`를 돌리기 전에는 개인 저장소가 제자리에 있는지 확인해야 한다(SHALL).

#### Scenario: 어느 것을 쓸지 갈라 적고 서로 가리킨다

- **WHEN** 스킬 문서를 읽는다
- **THEN** 링크 방식(이 스킬)과 복사 방식(`install.sh`)을 언제 쓰는지가 적혀 있다
- **AND** 고르는 안내의 본문이 있는 곳(`README.md`)을 가리킨다
- **AND** 같은 절차를 여기에 다시 서술하지 않는다

#### Scenario: 두 방식이 섞였을 때를 적었다

- **WHEN** 스킬 문서에서 `install.sh`와 섞이는 경우를 다루는 부분을 읽는다
- **THEN** 살아 있는 링크는 `install.sh`가 건너뛴다는 것이 적혀 있다
- **AND** 끊긴 링크일 때의 위험과, 돌리기 전에 개인 저장소를 확인하라는 말이 적혀 있다
